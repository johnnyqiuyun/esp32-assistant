# esp32s3-bringup 人性化改版（v0.3）设计

日期：2026-10-28　作者：Johnny Zong（需求）/ Claude（设计决定，用户授权直接完成，未逐条确认）
目标：把面板从"工程师调试界面"改成"任何人插上板子都看得懂、知道下一步该做什么"的界面，用于参赛展示。

## 原则

1. **先说结论，再给细节。** 每块板最上面一句大白话结论（运行正常 / 崩溃了 / 刚重启 / 被占用 …），细节折叠。
2. **每个问题都附下一步。** 不只说"失败"，而是"为什么 + 怎么办"。
3. **术语翻译成人话。** `rst:0xc (RTC_SW_CPU_RST)` → "CPU 复位（通常是程序崩溃后自动重启）"；RSSI -58 → 信号条 + "良好"。
4. **按钮看得见、主操作突出。** 不再用无边框按钮；当前最该做的那一步用主按钮（高亮）。
5. **不打扰。** 日志默认只显示最近 30 行，可展开到 200 行；可只看错误/警告或只看 Wi-Fi。
6. **危险操作讲清后果。** 烧录确认卡片写明文件、大小、目标板、预计时间、"会覆盖现有程序、过程中别拔线"。
7. **只用已在 Velloc 验证过的组件**（Box、Text、Button；颜色 green/red/yellow/cyan）。Velloc 不显示 Input，`Link` 打不开本地文件夹（spike 2）。

## 面板结构

- **顶部总览**：标题 + 一句总状态（"1 块板在线 · 一切正常" / "有 N 个问题需要处理" / "还没发现板子"）。
- **每块板一张卡片**
  - 标题行：`● ESP32-S3 · COM4`，圆点颜色 = 健康状态。
  - **结论行**（健康判定，见下）+ 下一步建议。
  - 规格摘要一行：`16MB Flash · 8MB PSRAM · 240 MHz · v0.2`；"详情"按钮展开 MAC、晶振、封装、识别时间。
  - **Wi-Fi 行**：已连接（SSID · IP · 信号条 + 文字 + dBm）/ 断开（原因的人话）/ 未发现 Wi-Fi 日志。RSSI 为正数时注明"不是标准 dBm 值"。
  - **重启原因**：最近一次复位原因的人话。
  - 操作按钮：识别芯片 / 重新识别；开始监视 / 暂停 / 继续 / 复位 / 清屏 / 停止 / 重试。
  - **运行日志**：标题带错误/警告计数；筛选（全部 · 错误/警告 · Wi-Fi）；显示更多/更少；着色保留。
  - **烧录**：空闲时给示例命令；确认卡片；进度条 `████████░░░░ 52%` + 已用时间 + "请勿拔线"；完成/失败卡片（失败附建议），可"知道了"关闭。
  - 日志文件夹路径（灰色小字）。
- **问题卡片**：缺驱动（含步骤）、找不到 Python/缺依赖（含命令）。
- **空状态**：三步排查清单（数据线、换 USB 口、设备管理器）。
- **底部**：刷新按钮 + "每 2 秒自动扫描"。

## 健康判定（优先级从高到低）

| 条件 | 色调 | 结论 |
|---|---|---|
| 识别中 | 黄 | 正在识别芯片… |
| 识别失败 | 红 | 识别失败：原因 + 建议 |
| 监视：崩溃 | 红 | 程序崩溃了 → 看红色日志 |
| 监视：被占用 | 黄 | 串口被其他程序占用 → 关掉后点重试 |
| 监视：等待重连 | 黄 | 等待板子重新连接… |
| 监视：最近 15 秒内重启且非上电 | 黄 | 板子刚重启（原因） |
| 监视：运行中 | 绿 | 程序运行正常 · 已运行 X |
| 监视：已暂停 | 无 | 监视已暂停 |
| 未识别 | 无 | 已连接，还不知道是什么芯片 → 点识别芯片 |
| 已识别、未监视 | 绿 | 芯片正常 · 点开始监视看运行日志 |

## 复位原因分类（按名字关键字）

POWERON → 上电或按了复位键；SW_SYS/SW → 程序主动重启（esp_restart）；SW_CPU → CPU 复位（多为崩溃后）；WDT → 看门狗超时（程序卡住）；BROWN_OUT → 供电不足；DEEPSLEEP → 深度睡眠唤醒；USB → USB 触发的复位；其他 → 原样显示。

## RSSI 分级

≥ -55 极好（4 格）；≥ -67 良好（3 格）；≥ -75 一般（2 格）；< -75 较弱（1 格）；≥ 0 非标准数值（不画信号条）。

## 不做

- 新的运行时能力（文件选择器、系统通知等，未经 Velloc 验证）。
- 改动监视/烧录的后台逻辑（v0.2 已验收）。
