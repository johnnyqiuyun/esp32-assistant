# esp32s3-bringup 第一阶段 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个 Claude 格式插件 `esp32s3-bringup`：Python CLI 只读地发现/检测 ESP32-S3，Velloc mod 面板自动显示"在线"、记得的芯片信息和"检测"按钮。

**Architecture:** 硬件操作全部在 `scripts/esp32_bringup.py`（pyserial + esptool，`--json` 输出）。Velloc mod（`hooks/`）只做三件事：定时跑 `ports --json`、按 USB 序列号把扫描结果和 `$.store` 里的检测记录合并、用户点按钮时跑 `probe --json`。合并和渲染是纯函数（`core.js`、`view.js`），用 `node --test` 测；接线在 `panel.js`。

**Tech Stack:** Python 3.13 + pyserial + esptool 5.6.0，测试用标准库 `unittest`（本机没装 pytest，不要装）；Velloc mods ABI 0.2（ESM JS），测试用 Node 22 内置 `node:test`；Windows 11 / PowerShell 5.1。

**Spec:** `J:\2_MY_WORK\ESP32\esp32s3-bringup\docs\design.md`（实现前必读，尤其第 4 节 Velloc 运行时 API 和第 5.3、6.1 节）

## Global Constraints

- **全程只读**：脚本里不得调用 write-flash / erase-flash / erase-region / write-mem / efuse 任何写操作。只允许 esptool 的 `flash-id`（含芯片信息）。
- **面板从不自动打开串口**：轮询只跑 `ports`（不打开端口）；`probe` 只在用户点"检测/重新检测"时运行。
- Python 路径：`%USERPROFILE%\AppData\Local\Programs\Python\Python313\python.exe`。不要用裸 `python`（是 Store 占位，退出码 49）。下文记为 `$PY`。
- 识别的 USB VID（大写十六进制）：`10C4`→`cp210x`，`1A86`→`ch34x`，`0403`→`ftdi`，`303A`→`espressif-usb`。其他 VID 一律忽略。
- 检测记录存 `$.store`，键 `boards`，值 `{ [recordKey]: { info, probedAt } }`；`recordKey = "VID:PID:SERIAL"`，无序列号的设备没有记录。
- 面板 id 与命令名都是 `esp32`。文案放 `locales/zh.json`、`locales/en.json`，面板文字不得硬编码。
- 插件根目录：`J:\2_MY_WORK\ESP32\esp32s3-bringup\`（下文路径都相对它）。
- 真板验证用 COM4（CP2102N，序列号 `E4DAC533F165EE11B81F966293CD958C`）。会复位板子一次，可接受。
- Velloc 面板里的东西 agent 看不见：凡是"在 Velloc 里看"的验证，都要请用户看并回报。

## Review Focus

1. **用户点"检测"时端口被占（`idf.py monitor` 开着）**：应显示"端口被占用"，且不覆盖、不删除该板已有记录 → Task 3 `test_classify_busy_*`、Task 5 `test_failed_probe_keeps_known_info`。
2. **同一块板换了 USB 口（COM4→COM7）**：按序列号仍认得，直接显示记录 → Task 5 `test_same_serial_new_port_is_known`。
3. **两块没有序列号的 CH340 同时插着**：各按端口独立显示"未检测"，不共用记录 → Task 5 `test_no_serial_never_known`。
4. **Python 找不到 / 缺 pyserial 或 esptool / 命中 Store 占位（退出码 49）**：面板显示原因和安装命令，mod 不抛异常 → Task 5 `test_python_candidates_order`、Task 7 Step 3。
5. **中文 Windows 下 esptool 报错是中文（"拒绝访问"）或含非 UTF-8 字节**：解析和分类照样工作 → Task 3 `test_classify_busy_chinese`、Task 3 Step 3 用 `errors="replace"`。

### Task 5: `hooks/core.js` — 扫描结果与记录合并（纯函数）

**Files:**
- Create: `hooks/core.js`
- Create: `tests/core.test.js`

**Interfaces:**
- Consumes：Task 2 的 `ports --json` 结构，Task 3 的 `probe --json` 结构
- Produces：
  - `recordKey(port) -> string | null`：`port.serial ? \`${port.vid}:${port.pid}:${port.serial}\` : null`
  - `reconcile(scan, records, transient) -> Board[]`
    - `scan`：`ports --json` 的 `ports` 数组
    - `records`：`{ [recordKey]: { info, probedAt } }`（来自 `$.store` 的 `boards`）
    - `transient`：`{ [portName]: { state: 'probing' } | { state: 'failed', reason, detail } }`
    - `Board = { port, bridge, serial, key, state, info, probedAt, reason, detail }`，`state ∈ 'unprobed' | 'known' | 'probing' | 'failed'`
    - 优先级：`transient` 的状态优先；`failed` 时如果有记录，`info/probedAt` 仍填上记录的内容
    - 顺序与 `scan` 相同
  - `applyProbe(records, port, result) -> records`：返回新对象。`result.ok` 时写入 `records[recordKey(port)] = { info: result, probedAt: result.probed_at }`；失败或无 key 时原样返回
  - `pythonCandidates(env) -> string[][]`：按顺序 `[[env.ESP_PYTHON]]`（有值时）、`[[\`${env.LOCALAPPDATA}\\Programs\\Python\\Python3NN\\python.exe\`]]`（NN 从 14 到 10 递减）、`[['py', '-3']]`
  - `newPorts(prevPortNames: string[], scan) -> string[]`：本次扫描中新出现的端口名（用于自动打开面板）

- [ ] **Step 1: 写测试** `tests/core.test.js`（`import { test } from 'node:test'`、`node:assert/strict`，从 `../hooks/core.js` 导入）：
  - `test_unknown_board_is_unprobed`：有 serial 但 records 为空 → `state 'unprobed'`、`info null`
