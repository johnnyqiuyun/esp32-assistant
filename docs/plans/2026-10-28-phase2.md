# esp32s3-bringup 第二阶段 Implementation Plan（串口监视器 + 烧录）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Velloc 面板里对确认是 ESP 的板子自动开始实时串口监视（状态摘要 + 着色 log），并能用本插件烧录合并 `.bin`，烧录/检测时自动让出串口。

**Architecture:** 新模块 `scripts/esp_monitor.py` 放所有监视/烧录逻辑：纯函数（摘要、行分级、镜像校验、进度解析）、文件协议（状态/控制/心跳文件）、可注入串口的 `Monitor` 循环、`FlashJob`。`esp32_bringup.py` 增加 `monitor …`、`flash`、`reset` 子命令并让 `probe`/`log` 走"暂停监视"。监视和烧录都是**分离的后台进程**，与面板只通过数据目录里的文件通信；面板每秒调 `monitor status --json` 取数据。

**Tech Stack:** 同第一阶段：Python 3.13 + pyserial + esptool 5.6.0（`unittest`），Velloc mods ABI 0.2 ESM（`node:test`），Windows only。

**Spec:** `docs/design-phase2.md`（必读第 3、5、6.2 节）；第一阶段背景：`docs/design.md`、`docs/spike-notes.md`。

## Global Constraints

- 只支持 Windows。`$PY` = `C:\Users\johnny.zong\AppData\Local\Programs\Python\Python313\python.exe`。JS 测试命令 `node --test "tests/*.test.js"`；Python `$PY -m unittest discover -s tests`。
- **唯一写 Flash 的路径是 `flash`**；没有 `--yes` 时只返回计划不执行。其余命令全部只读。
- 打开串口前必须 `dtr=False, rts=False`（否则复位板子）。
- 数据目录：环境变量 `ESP32_BRINGUP_HOME`，默认 `%LOCALAPPDATA%\esp32s3-bringup`。下设 `monitors\`、`logs\`、`jobs\`。测试一律把 `ESP32_BRINGUP_HOME` 指到临时目录。
- 常量（`esp_monitor.py` 顶部）：`ACK_TIMEOUT_S = 3`、`CTL_POLL_S = 0.2`、`HEARTBEAT_TIMEOUT_S = 600`、`REOPEN_INTERVAL_S = 1`、`LOG_ROTATE_BYTES = 5_000_000`、`LOG_KEEP_FILES = 50`（每块板）、`TAIL_LINES = 200`、`FLASH_BAUD = 460800`、`ESP_IMAGE_MAGIC = 0xE9`。
- 自动开始规则（设计 5.4）：只对 有检测记录的板子 或 VID `303A` 自动开始；手动停止后到拔出前不再自动开始。
- 监视进程只在端口**消失后重新出现**时自动重开；端口存在但被占用 → `busy`，不重试（等用户点"重试"）。
- 文案只放 `locales/zh.json`、`locales/en.json`，两边键集合相同。
- Velloc 不热加载：每次改 mod 后需请用户重启 Velloc 再验收；Velloc 界面的观察请用户回报。
- 真机烧录前**先问用户**，并先用只读的 `esptool read-flash` 备份当前固件。

## Review Focus

1. **Velloc 退出后监视进程不再心跳**：10 分钟后自行退出、释放 COM4，状态文件为 `stopped`/`no_heartbeat` → Task 3 `test_heartbeat_timeout_exits`。
2. **监视中拔线再插回（含原生 USB 复位重新枚举）**：状态 `waiting`，端口重新出现后自动重开且不复位板子 → Task 3 `test_port_disappears_then_reopens`。
3. **开始监视时端口被别的程序占着**：`busy`，之后不再尝试打开；`retry` 命令才再试 → Task 3 `test_busy_does_not_retry`、`test_retry_after_busy`。
4. **选错烧录文件**（ELF、空文件、首字节不是 0xE9、比 Flash 大）：拒绝且不碰串口 → Task 5 `test_check_image_*`。
5. **烧录中途失败（拔线/esptool 报错）**：任务状态 `failed`，监视仍被恢复 → Task 5 `test_flash_failure_still_resumes`。

### Task 2: `esp_monitor.py` 纯函数 — 实时摘要、镜像校验、进度解析

**Files:** Create `scripts/esp_monitor.py`；Create `tests/test_monitor_parse.py`；`tests/_load.py` 增加 `load_monitor()`（同 `load_cli` 方式加载 `scripts/esp_monitor.py`）

**Interfaces — Produces:**
- `class LiveSummary`：`feed(line: str, now: float) -> None`；`to_dict() -> dict`，字段：`status: 'running'|'crashed'|'unknown'`、`boots: int`、`last_reset: str|None`（如 `"0xc (RTC_SW_CPU_RST)"`）、`last_boot_at: float|None`、`errors: int`、`warnings: int`、`wifi: {state: 'unknown'|'connected'|'disconnected', ssid, ip, reason: int|None, rssi: int|None}`。规则：
  - `ESP-ROM:` → `boots += 1`、`last_boot_at = now`、`status = 'running'`；`rst:(…),boot:` → `last_reset`。
  - `Guru Meditation` / `abort() was called` / `panic'ed` → `status = 'crashed'`（直到下一次 `ESP-ROM:`）。
  - 行（去掉时间戳前缀后）以 `E (` 开头 → `errors += 1`；`W (` → `warnings += 1`。
  - `wifi:connected with (\S+?),?\s` → `state 'connected'`, `ssid`；`(?:sta ip|got ip):\s*(\d+\.\d+\.\d+\.\d+)` → `state 'connected'`, `ip`；`wifi:disconnected.*?reason:\s*(\d+)`（或 `reason=`）→ `state 'disconnected'`, `reason`, `ip None`；`(?i)\brssi\b\s*[:=]?\s*(-?\d+)` → `rssi`。
  - 第一个字符串非空前 `status` 为 `'unknown'`；收到任意行且未见过 `ESP-ROM:` 时为 `'running'`。
- `strip_stamp(line: str) -> str`：去掉 `^\d\d:\d\d:\d\d\.\d{3} ` 前缀。
- `check_image(path: str, flash_bytes: int|None) -> tuple[bool, str|None]`：`(False, 'missing'|'empty'|'not_esp_image'|'too_big')` 或 `(True, None)`。
- `parse_progress(text: str) -> int|None`：取最后一个 `\((\d+)\s?%\)`。
- `flash_size_bytes(size: str|None) -> int|None`：`"16MB"` → 16777216，`"4MB"` → 4194304，其他 None。

### Task 3: `Monitor` 循环与文件协议（可注入串口）

**Files:** Modify `scripts/esp_monitor.py`；Create `tests/test_monitor_loop.py`

**Interfaces — Produces（全部在 `esp_monitor.py`）：**
- `home() -> str`；`paths(port: str) -> dict`：`{state, ctl, hb}` = `monitors\<PORT>.json|.ctl|.hb`；`log_dir(key: str) -> str` = `logs\<key>`（key：序列号，无则端口名）。
- `read_json(path) -> dict|None`（不存在/损坏 → None）；`write_json_atomic(path, obj)`（写 `.tmp` 再 `os.replace`）。
- `send(port: str, cmd: str, timeout=ACK_TIMEOUT_S) -> dict|None`：写 ctl `{"cmd": cmd, "id": <递增整数>}`，等状态文件 `ack == id`，返回状态；超时 → None。`cmd ∈ pause|resume|stop|reset|retry`。
- `touch_heartbeat(port)`；`pid_alive(pid: int) -> bool`（ctypes `OpenProcess` + `GetExitCodeProcess == 259`）。
- `class Monitor(port, baud, key, *, open_serial, port_present, clock=time.time, sleep=time.sleep)`：
  - `open_serial(port, baud) -> 串口对象`（有 `read(n)`, `close()`, 可设 `rts`）；抛 `PermissionError` 或消息含 `PermissionError`/`拒绝访问`/`Access is denied` 的 `serial.SerialException` → busy；其他打开失败 → waiting。
  - `port_present(port) -> bool`
  - `step() -> bool`：做一轮（处理控制命令、读数据、写 log、心跳检查），返回 False 表示应退出。
  - `run()`：`while self.step(): sleep(CTL_POLL_S 以内)`。
  - 状态文件字段：`{pid, port, baud, key, state: 'running'|'paused'|'waiting'|'busy'|'stopped', reason, log, startedAt, updatedAt, ack, lines, summary}`（`summary` = `LiveSummary.to_dict()`，`lines` = 已写行数）。
  - 每行写入 log：`"%H:%M:%S.mmm " + 内容`；跨 `step` 的半行要缓冲；`\r\n`/`\n` 都算换行；解码 `utf-8, errors="replace"`。
  - `reset`：已打开时 `rts=True`，0.1 秒后 `rts=False`，继续读（不关端口）。
  - 心跳：`hb` 文件 mtime 距今 > `HEARTBEAT_TIMEOUT_S` → 关闭端口，`state 'stopped'`, `reason 'no_heartbeat'`，返回 False。启动时创建 hb。
  - log 轮转：当前文件 ≥ `LOG_ROTATE_BYTES` 开新文件；目录下超过 `LOG_KEEP_FILES` 删最旧的。

### Task 5: 烧录 — `flash` 命令与后台任务

**Files:** Modify `scripts/esp_monitor.py`、`scripts/esp32_bringup.py`；Create `tests/test_flash.py`

**Interfaces — Produces:**
- 任务文件 `jobs\<PORT>.flash.json`：`{pid, port, file, bytes, state: 'running'|'done'|'failed', percent, startedAt, finishedAt, reason, detail}`。
- `class FlashJob(port, file, baud, *, run_esptool, monitor_send, monitor_alive)`：`run() -> dict`：
  1. 若监视存活：`monitor_send(port,'pause')`，失败 → `failed/busy`；
  2. `run_esptool(argv, on_line)`：argv = `['--port', P, '--baud', str(baud), '--after', 'no-reset', 'write-flash', '0x0', file]`（esptool<5 时 `no_reset`/`write_flash`）；每行调用 `on_line`，用 `parse_progress` 更新 `percent` 并写任务文件；返回退出码与输出；
  3. 成功 → `state 'done'`, `percent 100`；失败 → `failed` + `classify_failure`；
  4. **无论成败**：之前有监视 → `monitor_send(port,'resume')` 然后 `monitor_send(port,'reset')`；没有监视 → 由 CLI 用串口 RTS 脉冲复位。
- CLI：`flash --port P FILE [--baud 460800] [--yes] [--wait] [--json]`：
  - 先 `check_image(FILE, flash_size_bytes(该端口最近 probe 的 flash.size，取不到为 None))`——"最近 probe"：CLI 没有面板记录，取不到就传 None；面板调用时传 `--flash-size 16MB`。增加可选参数 `--flash-size`。不通过 → `{ok:false, reason:'bad_image', detail:<reason>}`，退出码 1，不碰串口。
  - 无 `--yes` → `{ok:false, reason:'needs_yes', plan:{port, file, bytes}}`，退出码 2。
  - 同端口已有 `running` 的烧录任务 → `{ok:false, reason:'already_flashing'}`。
  - `--wait`：在当前进程跑 `FlashJob` 并把进度打印到 stdout（给 AI/命令行用）；否则分离启动 `flash run …`（内部子命令）并立即返回 `{ok:true, started:true, job:<任务文件路径>}`。
- `monitor status` 的 `flash` 字段读这个任务文件。
